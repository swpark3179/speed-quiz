# ⚡ 스피드 퀴즈

조직문화 소통 행사를 위한 실시간 스피드 퀴즈 웹서비스입니다.
관리자가 문제를 준비해 퀴즈방을 열고, 참가자는 **닉네임만 입력**해 휴대폰으로 참여합니다.
행사장 스크린에는 진행 화면을 띄우고, 정답 공개·순위 변동·시상식까지 게임쇼처럼 연출합니다.

- **관리자**: 로그인 → 문제은행(텍스트/HTML 문제, 보기 2~6개, 문제 그룹) → 퀴즈방 생성(문제·그룹 선택·순서·점수 방식·시상 인원) → 확정 → 진행
- **참가자**: 방 코드 또는 QR → 닉네임 → 대기실에서 서로 확인 → 큰 보기 버튼으로 응답 → 문제별 결과·최종 순위
- **진행 화면**: 대기실(QR·방 코드·참가자) → 문제·카운트다운 → 정답 공개(응답 분포) → 순위 변동 → 최종 결과 → 시상식(K등→1등 공개 애니메이션)
- 리눅스·윈도우 서버에서 `node` 하나로 실행, 별도 DB 서버 필요 없음(SQLite 내장), 모바일·PC 반응형

## 빠른 시작

요구 사항: **Node.js 22.13 이상** (pnpm 10은 개발·빌드할 때만 필요)

```bash
pnpm install
pnpm build          # 타입 검사 → 웹 빌드 → 서버 번들 → dist/
pnpm start          # node --disable-warning=ExperimentalWarning dist/server.js
```

처음 실행하면 관리자 계정이 자동으로 만들어지고 콘솔에 아이디/비밀번호가 출력됩니다.
`.env`의 `ADMIN_INITIAL_PASSWORD`로 미리 정할 수도 있어요. 로그인 후 바로 비밀번호를 바꾸세요.

| 화면 | 주소 |
|---|---|
| 관리자 | `http://<서버>:3000/admin` |
| 참가자 입장 | `http://<서버>:3000/join` (QR: `/join/<방코드>`) |
| 진행 화면(스크린) | 진행 페이지의 "진행 화면 열기" 또는 `/screen/<방ID>#key=<진행키>` |

### 개발 모드

```bash
pnpm dev            # API(:3000, tsx watch) + Vite(:5173, 휴대폰은 LAN IP:5173으로 접속)
pnpm test           # 단위 + 통합 테스트(Vitest)
pnpm e2e            # Playwright E2E (먼저 pnpm build)
pnpm loadtest -- --url http://localhost:3000 --password <관리자 비밀번호> --n 300
```

개발 중에는 `/dev/gallery`에서 디자인 토큰·보기 배치(2~6개 × 긴/짧은 보기)를 한눈에 확인할 수 있어요.

## 설정 (`.env`)

`.env.example`을 복사해 `.env`로 저장하세요. 경로는 앱 루트(`dist`의 상위 폴더) 기준입니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `HOST` / `PORT` | `0.0.0.0` / `3000` | 바인딩 주소 |
| `PUBLIC_BASE_URL` | (자동) | QR·입장 링크에 쓸 주소. 비우면 서버의 LAN IP를 사용 |
| `DATA_DIR` | `./data` | DB·업로드 이미지·백업 폴더 (네트워크 드라이브 금지) |
| `COOKIE_SECURE` | `false` | HTTPS로 서비스할 때 `true` (Secure 쿠키, HSTS) |
| `TRUST_PROXY` | `false` | 리버스 프록시 뒤에서 실행할 때 `true` |
| `SESSION_TTL_HOURS` | `12` | 관리자 로그인 유지 시간 |
| `ADMIN_INITIAL_USERNAME` / `ADMIN_INITIAL_PASSWORD` | `admin` / (자동 생성) | 관리자가 하나도 없을 때 만들 최초 계정 |
| `SIGNUP_ENABLED` | `true` | 로그인 화면의 관리자 셀프 가입 허용. `false`면 가입 링크가 사라지고 API도 거부 |
| `ANSWER_GRACE_MS` | `300` | 마감 직후 네트워크 지연을 감안한 유예 |
| `MAX_UPLOAD_MB` | `5` | 이미지 업로드 최대 크기 |

### 관리자 권한

- **메인 관리자**: 최초로 만들어진 계정(기존 DB는 가장 먼저 만든 계정)이 메인이 됩니다. 관리자 계정 추가·비활성화·비밀번호 재설정은 메인만 할 수 있어요.
  - **메인 권한 부여·해제**: 관리자 관리 화면에서 다른 계정에 메인 권한을 주거나 뺄 수 있어요. 바로 반영되고, 자기 자신의 권한은 해제할 수 없으며 활성 메인 관리자는 항상 한 명 이상 남아요.
  - **이용 현황**: 관리자별 문제·퀴즈방 개수, 종료된 게임과 참가자 수, 7/30/90일 일별 그래프를 볼 수 있어요. 숫자만 보여주고 문제·퀴즈방 내용은 메인도 볼 수 없어요.
- **셀프 가입**: 로그인 화면의 "가입하기"에서 아이디·닉네임·비밀번호만으로 가입하고, 아이디와 닉네임이 겹치지 않으면 바로 일반 관리자로 승인돼요. 개인정보는 받지 않고, 서비스가 언제든 종료될 수 있다는 안내에 동의해야 가입돼요. 닉네임은 관리자끼리 겹칠 수 없어요(대소문자 무시). 막으려면 `SIGNUP_ENABLED=false`.
- **일반 관리자**: 퀴즈방, 문제은행, 내 계정 화면만 사용합니다. 퀴즈방은 **본인이 만든 것만** 보이고(메인도 동일), 문제는 작성자가 **공개/비공개**를 고릅니다. 공개 문제는 다른 관리자가 보고 퀴즈방에 쓸 수 있지만 수정·삭제는 작성자만 할 수 있고, 복제하면 내 문제(비공개)가 됩니다.
- **문제 그룹**: 비슷한 문제를 폴더처럼 한 그룹으로 묶어 문제은행 목록을 간단하게 볼 수 있어요. 문제는 한 그룹에만 들어가고, 그룹은 목록에서 한 줄로 접혀 있다가 누르면 펼쳐져요.
  - **만들기·묶기**: 문제은행의 "새 그룹"으로 만들고, 목록에서 내 문제를 체크해 **그룹으로 이동**하거나(페이지 전체 선택 가능) 문제 편집 화면의 "그룹"에서 고르세요. 그룹 메뉴의 "이 그룹에 새 문제"로 바로 추가할 수도 있고, 그룹 안 문제를 복제하면 복사본도 같은 그룹 맨 뒤에 들어가요.
  - **순서**: 그룹을 펼쳐 "순서 바꾸기"로 끌어서 정해요. 퀴즈방에 그룹째 넣을 때 이 순서를 따라요.
  - **공개 규칙**: 그룹은 자기 문제만 담을 수 있고, 따로 공개 설정이 없어요. 공개 문제가 하나라도 있으면 다른 관리자에게도 그룹이 보이고, 그 안의 공개 문제만 보여요. 그룹 메뉴에서 그룹 문제를 한꺼번에 공개/비공개로 바꿀 수 있어요.
  - **퀴즈방에 통째로 넣기**: 퀴즈방 만들기의 문제 선택 단계에서 그룹의 **전체 추가**를 누르면 그 순간의 그룹 문제가 개별 문제로 추가돼요(최대 100개). 이후 그룹을 바꿔도 이미 만든 퀴즈방에는 반영되지 않고, 추가한 문제는 하나씩 빼거나 순서를 바꿀 수 있어요.
  - **삭제**: 그룹만 지우면 문제는 "그룹 없는 문제"로 돌아가고, "문제도 함께 삭제"를 고르면 그룹 안의 문제까지 지워져요.
- 퀴즈가 끝나면 퀴즈방 상세 화면에서 **리포트 다운로드**(단독 HTML 파일, 브라우저에서 PDF 인쇄 가능)를 받을 수 있어요.
- 참가자는 대기실에서 퀴즈가 시작되기 전까지 닉네임을 바꿀 수 있어요(중복 닉네임은 거부).

관리자 계정은 CLI로도 관리할 수 있어요. (`admin:create`로 만든 첫 계정은 메인, 이후 계정은 일반 관리자)

```bash
node dist/server.js admin:create --username kim --name 김진행
node dist/server.js admin:passwd --username kim
```

## 게임 규칙

- **시간**: 서버가 출제 시각·보기 공개 시각(준비 카운트다운)·마감 시각을 정하고, 모든 화면이 서버 시계에 맞춰 카운트다운합니다. 제한시간이 끝나면 자동 마감, 관리자가 먼저 마감할 수도 있고, 접속 중인 전원이 답하면 바로 마감(옵션)됩니다.
- **응답**: 첫 응답만 인정됩니다. 정답 여부는 마감 전까지 휴대폰·스크린에 절대 전송되지 않습니다.
- **점수 방식**(방 생성 시 선택)
  - 균등 점수: 정답자 모두 같은 점수
  - 선착순 차등(기본): `기본점 + max(최소 보너스, 1등 보너스 − (순위−1)×감소폭)` — 예) 1000, 950, 900 …
  - 순위별 보너스: 상위 N명에게 표에 정한 보너스
  - 시간 비례: 남은 시간에 비례
  - 문제마다 점수 배수(×0.5~×3) 지정 가능
- **화면 역할**: 진행자 휴대폰(`/admin/.../live`)은 진행 컨트롤 전용이라 문제·보기·정답을 미리 보여주지 않고 진행 상황(응답 수·타이머·정답률)만 표시합니다. 문제는 진행 화면(PC·빔)과 참가자 휴대폰에만 나옵니다.
- **참가자 순위 위젯**: 참가자 휴대폰 상단에 TOP 5와 내 순위가 항상 표시됩니다(접기 가능). 문제가 마감되고 정답 연출이 끝난 뒤에 갱신되며, 대기실·시상식 중에는 숨기고 '문제 후 순위 공개'를 끄면 나오지 않습니다.
- **동점 처리**: 총점 → 정답 수 → 정답 응답 시간 합(짧을수록) → 먼저 입장한 순
- **시상**: 상위 K명(0~10, 점수 0점 제외). 진행 화면에서 K등부터 1등까지 한 명씩 공개하며, 당첨자 휴대폰은 자기 카드가 뒤집히는 순간 축하 화면으로 바뀝니다.

## 구조

```
apps/server   Fastify + Socket.IO + node:sqlite — REST API, 실시간 게임 엔진(RoomEngine)
apps/web      React + Vite + Tailwind v4 + motion — 참가자/진행 화면/관리자 UI
packages/shared  zod 스키마, 점수 계산, 진행 단계, 소켓 이벤트 계약(서버·웹 공용)
e2e/          Playwright 시나리오      tools/loadtest.ts  300명 부하 테스트
```

- 게임 상태는 방마다 서버 메모리의 `RoomEngine`이 결정하고, 모든 변화는 SQLite에 먼저 기록한 뒤 전송합니다. 서버가 재시작돼도 진행 중이던 방과 타이머가 복구됩니다.
- HTML 문제는 저장할 때(서버)와 그릴 때(브라우저) 같은 허용 목록으로 두 번 정제하고, CSP로 스크립트 실행을 막습니다.
- CSS·이미지가 든 HTML 묶음(파일 여러 개·폴더·zip)은 문제 편집 화면의 **HTML 파일 불러오기**로 가져와요. 이미지는 업로드하고 CSS는 허용된 inline style로 옮기며 JS는 제거해, 결과는 같은 정제 경로를 거칩니다. 검토 내용은 [docs/html-import.md](docs/html-import.md)를 보세요.
- 폰트(Pretendard, Black Han Sans)·QR·효과음(Web Audio 합성)이 모두 로컬에 있어 **폐쇄망에서도 외부 요청 없이** 동작합니다.

배포(리눅스 systemd, 윈도우 서비스, Docker, 리버스 프록시)는 [docs/deploy.md](docs/deploy.md)를 참고하세요.
